# GARVIS アトラクター記憶プロトタイプ

著者: Adrien D. Thomas

状態: 決定論的ソフトウェア実験

科学的境界: このプロトタイプは、意識、自我、同一性の持続、真の AGI、生物学的同等性、量子的検証、あるいは物理法則を確立するものではありません。

## 目的

Hopfield スタイルの連想記憶コンポーネントを構築します:

1. 分散した相互作用重みに双極パターンを保存します。
2. 完全、部分的、またはノイズを含む手がかりを受け付けます。
3. 反復的に安定状態へと収束します。
4. 収束、復元精度、エネルギー、失敗を報告します。

ネットワークの重みが記憶の保存機構です。保存なく記憶が存在するかのように記述してはなりません。

## 状態表現

保存パターンは -1 と +1 のみを含みます。

想起手がかりは 0 を含んでもよく、これは消去または不明な値を表します。

すべてのパターンは同一の長さでなければなりません。

## 重みの構成

次元 n の保存パターン x_k に対して:

W = (1 / n) * sum of outer_product(x_k, x_k)

重み行列 W は対称でなければなりません。

すべての対角成分は 0 でなければなりません。

想起は、ファイル名、データベースキー、パターン識別子、またはルックアップインデックスではなく、重み行列を使用しなければなりません。

## 収束規則

決定論的非同期ニューロン更新を使用します。

各ニューロンについて:

field = sum(W[i][j] * state[j])

field が正ならニューロンを +1 に設定します。
field が負ならニューロンを -1 に設定します。
field が 0 の場合は現在の値を保持します。
field と現在値がともに 0 の場合は +1 を使用します。

1 回のスイープで全ニューロンを一度ずつ更新します。

完全な 1 スイープで変更が生じなくなったとき、ネットワークは収束します。

有限の最大スイープ回数は必須です。

## エネルギー

完全に双極の状態について:

E = -0.5 * state_transpose * W * state

決定論的非同期の収束中、エネルギーは増加しないはずです。

これはソフトウェア上の不変条件であり、物理エネルギーの証拠ではありません。

## 必須測定項目

各想起結果は次を報告しなければなりません:

- 最終状態;
- 収束/非収束;
- スイープ回数;
- 状態変更の総数;
- エネルギーの推移;
- ターゲットが与えられた場合の厳密一致;
- ターゲットが与えられた場合の Hamming 距離;
- 警告または失敗理由。

## 必須テスト

実装は以下をテストしなければなりません:

1. 空パターンの拒否。
2. 次元不整合の拒否。
3. 無効値の拒否。
4. 対称な重みとゼロ対角。
5. 保存済みの完全手がかりからの厳密想起。
6. 部分手がかりからの想起。
7. 制御されたビット反転ノイズからの想起。
8. 同一シードでの決定論的結果。
9. 有界な非収束時の取り扱い。
10. 非同期エネルギーの非増加。
11. 偽アトラクターの報告。
12. 複数パターンにおける容量と干渉。

成功、失敗、あいまいな想起はすべて可視のままでなければなりません。

## ベースライン

実験はアトラクター想起を以下と比較しなければなりません:

1. 明示的な最近傍パターンのルックアップ・ベースライン。
2. 学習した連想的収束を用いず、消去ビットを決定論的に補完するノーメモリ・ベースライン。

この比較は、別途事前登録された実験がない限り、記述的なものです。

## エンジニアリングの境界

最初の実装は Python 標準ライブラリのみを使用します。

提案モジュール:

src/garvis/attractor_memory.py

提案テスト:

tests/garvis/test_attractor_memory.py

メモリモジュールが行ってはならないこと:

- ファイルシステムへの書き込み;
- ネットワークアクセス;
- サブプロセスの実行;
- Git 操作;
- シークレットアクセス;
- モデル呼び出し;
- 外部アクション。

## 将来の GARVIS 統合

後の統合では、アトラクターの出力を任意のコンテキストとして提供するかもしれません。

想起内容には出所情報と信頼度を含め、決して無条件の事実として扱ってはなりません。

アトラクター記憶は、セッション履歴、リポジトリ根拠、科学的主張、承認、外部アクション権限から分離されたままにします。
