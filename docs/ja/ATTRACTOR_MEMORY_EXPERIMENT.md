# GARVIS アトラクタ・メモリ プロトタイプ

Author: Adrien D. Thomas

Status: 決定的なソフトウェア実験

Scientific boundary: このプロトタイプは、意識、自我、同一性の持続、真の AGI、生物学的同等性、量子的検証、あるいは物理法則を確立するものではありません。

## Purpose

Hopfield 型の連想メモリコンポーネントを構築します:

1. 二極性パターンを分散した相互作用重みに格納します。
2. 完全・部分・ノイズを含む手がかりを受け付けます。
3. 反復的に安定状態へと収束します。
4. 収束、復元精度、エネルギー、失敗を報告します。

ネットワークの重みが記憶のメカニズムです。ストレージなしに記憶が存在すると記述してはなりません。

## State representation

保存パターンは -1 と +1 のみを含みます。

想起の手がかりは 0 を含んでもよく、これは消去または不明な値を表します。

すべてのパターンは同一の長さでなければなりません。

## Weight construction

次元 n の保存パターン x_k に対して:

W = (1 / n) * sum of outer_product(x_k, x_k)

重み行列は対称でなければなりません。

すべての対角成分は 0 でなければなりません。

想起は、ファイル名、データベースキー、パターン識別子、またはルックアップインデックスではなく、重み行列を使用しなければなりません。

## Settling rule

決定的な非同期ニューロン更新を使用します。

各ニューロンについて:

field = sum(W[i][j] * state[j])

field が正ならニューロンを +1 に設定します。
field が負ならニューロンを -1 に設定します。
field が 0 の場合、現在の値を保持します。
field と現在の値がともに 0 の場合は +1 を使用します。

1 回のスイープは、すべてのニューロンを 1 度ずつ更新します。

完全な 1 スイープで変更が発生しなければ、ネットワークは収束します。

有限の最大スイープ回数は必須です。

## Energy

完全に二極性の状態に対して:

E = -0.5 * state_transpose * W * state

決定的な非同期収束の間、エネルギーは増加しないはずです。

これはソフトウェアの不変条件であり、物理的エネルギーの証拠ではありません。

## Required measurements

各想起結果は以下を報告しなければなりません:

- 最終状態;
- 収束済みか非収束か;
- スイープ回数;
- 状態変更の合計数;
- エネルギーの推移;
- 目標が与えられた場合の厳密一致;
- 目標が与えられた場合のハミング距離;
- 警告または失敗理由。

## Required tests

実装は次をテストしなければなりません:

1. 空パターンの拒否。
2. 次元不整合の拒否。
3. 無効値の拒否。
4. 対称な重みとゼロ対角。
5. 完全な保存手がかりからの厳密想起。
6. 部分的手がかりからの想起。
7. 制御されたビット反転ノイズからの想起。
8. 同一シードを用いた決定的な結果。
9. 有界な非収束処理。
10. 非同期エネルギーの非増加。
11. 偽アトラクタの報告。
12. 複数パターンでの容量と干渉。

成功・失敗・曖昧な想起はすべて可視のままにする必要があります。

## Baselines

実験は次とアトラクタ想起を比較しなければなりません:

1. 明示的な最近傍パターン参照のベースライン。
2. 学習した連想的な収束なしに、消去ビットを決定的に埋めるメモリなしベースライン。

別個の実験が事前登録されていない限り、比較は記述的です。

## Engineering boundary

最初の実装は Python 標準ライブラリのみを使用します。

Proposed module:

src/garvis/attractor_memory.py

Proposed tests:

tests/garvis/test_attractor_memory.py

メモリモジュールが行ってはならないこと:

- ファイルシステムへの書き込み;
- ネットワークアクセス;
- サブプロセス実行;
- Git 操作;
- シークレットへのアクセス;
- モデル呼び出し;
- 外部アクション。
