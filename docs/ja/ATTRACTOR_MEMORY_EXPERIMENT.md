# GARVIS アトラクタメモリ プロトタイプ

著者: Adrien D. Thomas

ステータス: 決定論的なソフトウェア実験

科学的境界: このプロトタイプは、意識、感受性、同一性の持続、真の AGI、生物学的同等性、量子的検証、または物理法則を確立しません。

## 目的

Hopfield スタイルの連想メモリ構成要素を構築します。要件は次のとおりです:

1. 分散した相互作用重みへ双極パターンを格納する。
2. 完全、部分、またはノイズを含む手掛かりを受け付ける。
3. 反復的に安定状態へ収束する。
4. 収束、復元精度、エネルギー、失敗を報告する。

ネットワークの重みがストレージ機構です。ストレージなしにメモリが存在すると記述してはなりません。

## 状態表現

格納パターンは -1 と +1 のみを含みます。

想起の手掛かりは 0 を含むことがあり、これは消去または不明な値を表します。

すべてのパターンは同一の長さでなければなりません。

## 重みの構築

次元 n の格納パターン x_k に対して:

W = (1 / n) * sum of outer_product(x_k, x_k)

重み行列は対称でなければなりません。

すべての対角要素は 0 でなければなりません。

想起はファイル名、データベースキー、パターン識別子、ルックアップインデックスではなく、重み行列を使用しなければなりません。

## 安定化規則

決定論的な非同期ニューロン更新を使用します。

各ニューロンに対して:

field = sum(W[i][j] * state[j])

field が正ならニューロンを +1 に設定します。
field が負ならニューロンを -1 に設定します。
field が 0 の場合、現在の値を保持します。
field と現在値がともに 0 の場合は +1 を使用します。

1 回のスイープで各ニューロンを 1 度ずつ更新します。

完全な 1 スイープで変更が生じないとき、ネットワークは収束します。

スイープ回数の有限な上限は必須です。

## エネルギー

完全に双極の状態に対して:

E = -0.5 * state_transpose * W * state

決定論的な非同期安定化の過程で、エネルギーは増加してはなりません。

これはソフトウェアの不変条件であり、物理的エネルギーの証拠ではありません。

## 必須測定

各想起結果は以下を報告しなければなりません:

- 最終状態;
- 収束済みか非収束か;
- スイープ回数;
- 状態変更の総数;
- エネルギートレース;
- 目標が与えられた場合の完全一致可否;
- 目標が与えられた場合のハミング距離;
- 警告または失敗理由。

## 必須テスト

実装は以下をテストしなければなりません:

1. 空パターンの拒否。
2. 次元不整合の拒否。
3. 不正値の拒否。
4. 対称な重みとゼロ対角。
5. 完全な格納手掛かりからの厳密想起。
6. 部分手掛かりからの想起。
7. 制御されたビット反転ノイズからの想起。
8. 同一シードでの決定論的結果。
9. 非収束に対する上限制御。
10. 非同期エネルギーの非増加。
11. 偽アトラクタの報告。
12. 複数パターンにおける容量と干渉。

成功・失敗・曖昧な想起はいずれも可視のままでなければなりません。

## ベースライン

実験はアトラクタ想起を次と比較しなければなりません:

1. 明示的な最短距離パターンのルックアップ・ベースライン。
2. 学習された連想的安定化を用いず、消去ビットを決定論的に埋めるノーメモリ・ベースライン。

別個の実験が事前登録されていない限り、比較は記述的です。

## エンジニアリング境界

最初の実装は Python 標準ライブラリのみを使用します。

提案モジュール:

src/garvis/attractor_memory.py

提案テスト:

tests/garvis/test_attractor_memory.py

メモリモジュールが実行してはならないこと:

- ファイルシステムへの書き込み;
- ネットワークアクセス;
- サブプロセス実行;
- Git 操作;
- シークレットアクセス;
- モデル呼び出し;
- 外部アクション。

## 将来の GARVIS 統合

後続の統合では、アトラクタ出力を任意のコンテキストとして提供する場合があります。

想起コンテンツは出所情報と確信度を含み、決して無批判な真実として扱ってはなりません。

アトラクタメモリは、セッション履歴、リポジトリ証拠、科学的主張、承認、外部アクション権限とは分離されたままです。
